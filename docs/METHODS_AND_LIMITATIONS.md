# Experimental protocol and reproducibility limits

1. **Selection and duplication.** The publication package uses one shared `cropaggregation` package selected from the working experiment implementations. Historical `main`, `main_1`, `main_copy`, backup entry points, unused sixth models, PASTIS branches, unrelated Lushan class-weight scripts and standalone paper-layout scripts are not distributed as parallel source trees. Numeric uncertainty and feature-preparation routines needed for the stated scope are retained.
2. **Archived results versus new training.** The repository recomputes historical results from frozen pixel probabilities. The selected training code preserves the corresponding fixed/spatial/temporal protocols but now stores fixed-training validation probabilities and normalization dtype explicitly. MC Dropout random draw order and software/hardware can affect new probabilities; stochastic retraining is not claimed to reproduce every archived decimal.
3. **Normalization.** Historical fixed runs produced float32 percentile parameters under NumPy 2.x. Reading their decimal CSV directly as float64 can change XGBoost threshold decisions. Archived fixed-checkpoint inference restores float32; new checkpoints use `normalization.npz` to retain the saved dtype. This correction affects loading, not the archived model weights or probabilities.
4. **Spatial calibration.** Parameter selection reuses ordinary spatial OOF predictions; the original workflow is not a strictly nested spatial experiment. The code and results preserve that method rather than claiming a leakage-free nested protocol. Geographic polygon-overlap tables are also supplied; polygon intersection is not by itself proof of duplicate evaluation pixels.
5. **Spatial aggregation implementation.** The selected implementation replaces repeated per-parcel DataFrame indexing with array reductions for the identical distance-weighted mean. It was compared with the original numerical routine and the full archived spatial metric matrix. No new parameter-selection rule was introduced.
6. **NLL.** Computation preserves the historical `1e-12` probability clipping. A prior manuscript description used `1e-15`. They gave the same fixed-test results in the earlier clipping audit; that does not justify silently changing the stated protocol or extending the conclusion to all possible inputs.
7. **Uncertainty.** Model evaluation retains MC mean probabilities, entropy, expected entropy and epistemic mutual information. The numerical uncertainty entry point evaluates parcel entropy/confidence risk and averages an archived pixel epistemic column only where it exists. It does not reconstruct missing MC samples or infer unobserved uncertainty components from a single probability vector. It uses the archived risk-coverage integration convention and stable sorting of ties.
8. **Feature provenance.** The historical GEE recipe names B2/B3/B4/B8/NDVI/EVI/GNDVI/YCI/SAVI/VV/VH. A previous manuscript description named NDWI/RVI instead. Raster band descriptions are absent. The distributed 77 feature values are preserved and sampled against the images; the author must resolve the feature-name discrepancy before making a definitive manuscript claim. The GEE recipe is not presented as a newly verified reconstruction of all original acquisitions.
9. **Small parcels.** The primary-season small-parcel correlation concerns 25 test parcels, not the older 95-parcel analysis. Empty size groups are missing values, not zero effects. Temporal benefits depend on transfer direction.
10. **Validation boundary.** All archived checkpoints are load-tested with a finite forward pass. Repository preparation includes an XGBoost training/prediction smoke run, not a fresh 350-checkpoint training campaign. Exact checks and tolerances are reported separately in `VALIDATION.md` and machine-readable evidence.
